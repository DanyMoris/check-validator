СВЕРКА ПОСТУПЛЕНИЙ И ПОДТВЕРЖДЕНИЕ ДОКУМЕНТОВ
==============================================

База данных
-----------
Уже подключена. Один файл SQLite: data/bot.db (на этом компьютере, в git
не попадает).

  submissions      — история проверок (хеш файла, вердикт, кто прислал)
  ledger_entries   — журнал реальных поступлений (сумма в копейках, дата,
                     источник, каким файлом уже «съедено»)
  ledger_coverage  — периоды, за которые выписка считается полной
  user_prefs       — режим проверки на пользователя: ledger или structure

Отдельного сервера баз данных нет. Файл создаётся при первом запуске бота.


Два режима после /start
-----------------------
После /start бот спрашивает, есть ли доступ к выпискам по счёту.

  Есть выписки (ledger)
      Журнал работает как раньше. Чек без записи — НЕ ПОДТВЕРЖДЁН.
      Совпадение суммы и даты или подпись ГОСТ — ПОДТВЕРЖДЁН.
      Word / «печать в PDF» / дописка — ПОДДЕЛКА.

  Нет выписок (structure)
      Журнал не читается и команды /income, /statement не используются.
      Шаблон банка совпал, файл не гоняли через чужую программу — ПОДЛИННЫЙ.
      Это про PDF, не про деньги на счёте. Подмена одной цифры в живом
      шаблоне банка здесь тоже выглядит «подлинной» — против этого был журнал.


Два независимых пути к вердикту «ПОДТВЕРЖДЁН»
---------------------------------------------
1) Электронная подпись банка в самом PDF (сейчас — справки ВТБ).
2) Совпадение суммы и даты с записью в журнале поступлений на ВАШЕМ счёте.

Достаточно одного пути. Чек почти никогда не подписан — ему нужен путь 2.
Справка ВТБ подписана — ей путь 2 не обязателен.


Путь 1. Как подтверждается справка БЕЗ сверки со счётом
-------------------------------------------------------
В PDF справки ВТБ встроена подпись ГОСТ Р 34.10-2012. Бот проверяет:

  - подпись есть и покрывает файл целиком;
  - математика подписи сходится с открытым ключом;
  - хеш содержимого совпадает с тем, что банк подписал (файл не правили);
  - ИНН подписанта в белом списке (7702070139 — Банк ВТБ).

Если всё сходится — «ПОДТВЕРЖДЁН». Это доказательство, что документ выпустил
банк и его не меняли. Это НЕ доказательство, что деньги легли именно на
вашу карту. Для справки «по месту требования» обычно достаточно первого.

Справки Сбера в текущих образцах такой встроенной подписи не содержат.
Они остаются «НЕ ПОДТВЕРЖДЁН», пока не сработает журнал (или пока не
подключим отдельный файл .sig / УКЭП Сбера — этого ещё нет).


Путь 2. Как проверяется «деньги реально пришли»
-----------------------------------------------
Публичного API «Сбер, подтверди этот чек» для личного счёта нет.
Источник правды — ваши входящие операции, которые вы кладёте в журнал.

Когда присылают PDF чека:

  1. Из файла читаются сумма и дата.
  2. В журнале ищется та же сумма в окне ±48 часов.
  3. Результат:
       нашли свободную запись          → ПОДТВЕРЖДЁН
                                         (запись помечается этим файлом)
       тот же файл проверяют снова     → снова ПОДТВЕРЖДЁН
       сумма уже «съедена» другим PDF  → ПОДДЕЛКА (повторное использование)
       записи нет                      → НЕ ПОДТВЕРЖДЁН
                                         (совпадения с журналом нет; это не
                                         подделка, если структура в порядке)
       документ — исходящий чек        → в журнал не пишется; при проверке
                                         не объявляется подделкой из-за
                                         отсутствия в поступлениях

Как наполнять журнал СЕЙЧАС (уже работает в боте и в CLI):

  /income 410 02.09.2026 13:02
      Одна ручная запись. Покрытия нет: отсутствие прихода само по себе
      не считается подделкой.

  /income  +  CSV (две и больше строк: дата, сумма)
      Создаётся покрытие от первой до последней даты. Нет такого прихода
      → НЕ ПОДТВЕРЖДЁН, не подделка.

  /income  +  PDF своей ВХОДЯЩЕЙ справки
      Сумма и дата из справки попадают в журнал. Покрытия нет.
      Чек отправителя (исходящий перевод) в журнал не записывается.

  /income  +  SMS Сбера (вставить текст)
      Одно зачисление, покрытия нет. SMS ВТБ и Альфы обычно не приходят
      (в приложении услуга платная и часто выключена).

  /statement
      Один файл выписки по счёту (не по карте). Выписка по карте не содержит
      переводов СБП на счёт — бот её отклонит и попросит выписку по счёту.
      Пересекающиеся периоды сливаются; уже внесённые зачисления не дублируются.
      Следующий файл — снова /statement или /income.

  /coverage 01.09.2026 11.09.2026
      Вручную сказать: выписка за эти дни полная.

Команды: /ledger — посмотреть журнал, /withdraw — убрать ошибочный CSV/PDF,
/ledger_reset — очистить журнал (кнопка «Да»), /cancel — отмена.


Два репозитория на GitHub — ещё не подключены
---------------------------------------------
Это не новый «детектор», а автоматическая кормушка для того же журнала.

1) glebasos/Sber2Excel
   https://github.com/glebasos/Sber2Excel
   Разбирает PDF выписки Сбера (личный дебетовый счёт, шаблон 2025–2026)
   в таблицу операций.

   Сейчас PDF выписки Сбера разбирается своим парсером (не Sber2Excel):
   «Выписка по платёжному счёту», период «За период … — …», плюс у первой
   суммы — зачисление. Справка по одной операции покрытием не становится.

   Как использовать: выгрузка выписки из СберБанк Онлайн → бот → разбор
   в ledger_entries + покрытие периода. УКЭП в PDF Сбера пока отдельно
   не проверяется — доверие к выписке такое же, как к файлу, который вы
   сами выгрузили.

   Сейчас разбирается PDF выписки ВТБ по счёту, выписка Альфа-Банка
   по счёту («За период с … по …», сумма в RUR, часто на следующей строке)
   и выписка Сбера по платёжному счёту, справка Т-Банка о движении средств.
   Выписку по карте просим не присылать.
   Зачисления идут в журнал, расходы и HOLD нет. Одна и та же сумма в тот же день
   из CSV и PDF не создаёт вторую свободную запись. Период из шапки — покрытие,
   даже если зачислений ноль. Выписку по счёту можно просто прислать боту файлом.

   SMS Сбера о зачислении («СЧЁТ… +Nр») можно вставить текстом в бота.
   У ВТБ и Альфы таких SMS обычно нет.

2) Пересылка пушей с Android (PulseGate и аналоги)
   Не делаем: у клиента iPhone, NotificationListener на Android не подходит.
   SMS Сбера по-прежнему можно скопировать из «Сообщений» и вставить в бота.
   Это «деньги пришли», но не «я знаю все платежи за день». Без выписки
   по счёту отсутствие записи ≠ подделка.

Разумный порядок: ручной ввод и CSV (уже есть) → PDF-выписка по счёту
(Сбер / ВТБ / Альфа / Т-Банк) → SMS Сбера вставить в бота с iPhone.


Чего сознательно нет
--------------------
- Платного банковского API для юрлица (у вас личный счёт).
- Облачной базы и Redis.
- Проверки «справка Сбера по УКЭП» — отдельный этап, позже.
